# ТЗ: Executive English — личный аудио-тренажёр активного извлечения (v1)

> Статус: **v1 — после челленджа.** Прогнан через Claude.ai (Opus 4.8) + ChatGPT (Extended). Полная критика и синтез: `~/Documents/AI/Claude/_inbox/challenge-2026-05-29-0035.md`.
> Дата: 2026-05-29

## 0. Что изменилось от v0 → v1 (ключевой разворот)

Челлендж дал сильную конвергенцию двух моделей. Главные пересмотры:

1. **Цель сменилась: не «узнавание», а «производство речи».** Дефолтным режимом становится **Active Recall** (стимул → тишина → проговариваешь вслух → reveal/TTS), а не пассивный listening drill. Listening понижен до вспомогательного.
2. **Фоновое аудио на iOS — это server-rendered gapless audio, а не JS-плейлист.** Паузы и повторы зашиты *внутрь* аудиофайла; клиент крутит один `<audio>`-элемент. JS-таймеры в фоне на iOS не работают — это P0-риск, не деталь.
3. **Offline-first обязателен** (метро = нет сети): Service Worker + Cache API на устройстве, не только серверный кэш.
4. **Строгий JSON-schema = источник правды.** LLM — одноразовый импортёр с diff/approval, а не «парсер на каждый раз».
5. **LLM provider abstraction** вместо опоры на один «бесплатный прокси».
6. **Span-based хранение мнема-якорей**, не regex.

## 1. Контекст и цель

Алексей учит «Executive English» — наборы лидерских речевых фраз, организованных в тематические «лестницы» (батчи/модули). Каждый батч = набор английских выражений по нарастанию (напр. интенсивность несогласия), разбитый на зоны, плюс мнемоническая история для запоминания.

Сейчас фразы живут в чатах Claude.ai. Нужен **личный веб-портал на Hetzner**, куда Алексей загружает батчи фраз и тренирует их с телефона.

**Цель (уточнена):** довести фразы до **автоматизма в речи** — не «узнать на слух», а «вытащить из памяти и произнести под давлением момента». Узнавание на слух — побочный, не главный результат.

## 2. Пользователь и режим использования

- **Один пользователь** (Алексей). Мультиюзера нет.
- **Mobile-first.** Главный сценарий: телефон, наушники, экран заблокирован, в фоне (метро без сети, прогулка, зал). → отсюда жёсткие требования offline + gapless audio.
- Десктоп — для **управления батчами** (загрузка/редактирование/approval).
- Авторизация: один пароль / basic-auth за reverse-proxy с HTTPS. **Стоимостные эндпоинты (TTS/генерация) НЕ публикуются** в открытый интернет (см. §5, §10).

## 3. Доменная модель

Извлечена из реального формата в Claude.ai (модули «Восхождение», «Раскопки», «Сцена»).

### Батч (= модуль)
- `title` — напр. «Восхождение — лестница несогласия»
- `theme/axis` — ось градации, напр. «сила несогласия: от мягкого к жёсткому»
- `difficulty`, `version`, `status` (draft / approved), `source_text` (исходный сырой текст для аудита)
- `zones[]` — упорядоченные зоны: напр. Curious (1-3), Cautious (4-7), Candid (8-11). Каждая зона: `title`, `order_index`, `intensity_label`
- `phrases[]` — упорядоченный список фраз
- `mnemo_story` — мнема-история (текст + spans якорей)

### Фраза
- `order_index` — порядковый номер в лестнице (1..N)
- `anchor` (keyword) — ключевое слово-якорь (обычно глагол): `Understand`, `Walk`, `Outlier`…
- `phrase_en` — полная английская фраза: «Help me understand the thinking there.»
- `gloss_ru` (опц.) — когда/зачем применять, по-русски
- `intensity_score` — числовая позиция на оси градации (для калибровочного режима)
- `zone_id` (опц.), `tags[]`

### Мнема-техника
- `story_ru` — короткая яркая история на русском, где **ключевые слова всех фраз идут по порядку**.
  Пример: *«Ты хочешь **UNDERSTAND** гору, поэтому **WALK** к началу тропы и **READ** карту… одинокий **OUTLIER** на пике… отвечаешь **STRAIGHT**.»*
- `spans[]` — **позиционные якоря**: `{anchor_id, phrase_id, start, end}`. Хранятся как смещения в тексте, **не** через regex/поиск по слову (иначе падежи, повторы слов и пунктуация ломают раскрытие по тапу). В портале подчёркиваются; тап раскрывает полную фразу.

## 4. Функциональные требования

### 4.1 Управление батчами (desktop/admin)
- Загрузка батча через **вставку сырого текста из Claude** (формат «N. Keyword → phrase» + блок мнема-истории).
- **Import pipeline:** сырой текст → LLM-импортёр предлагает строгий JSON → backend валидирует по схеме → UI показывает редактируемую таблицу + **diff** → пользователь правит и **подтверждает (approval gate)** → сохраняется.
- **LLM = одноразовый конвертер, не источник истины.** После approve канон — JSON; повторно LLM-ом по нему не ездим, правки руками не затираются.
- Ручное редактирование: добавить/изменить/удалить фразу, переупорядочить, отредактировать зоны, мнема-текст и spans якорей.
- Список батчей, переименование, soft-delete. Export/import всего батча в JSON (бэкап + перенос).

### 4.2 Плеер — Режим 1 (ДЕФОЛТ): Active Recall / Anticipation
Главный режим — он один даёт автоматизм в речи.
- Для каждой фразы: **стимул** (RU-смысл или короткий бизнес-сценарий + требуемая интенсивность) → **тишина 3–5 сек** (зашита в аудио) → пользователь **проговаривает вслух** → TTS даёт **правильный английский вариант** → пауза для повтора (shadowing).
- Порядок прохождения настраивается: **ordered → random within zone → full random** (см. §4.5). По умолчанию сначала порядок.
- Калибровочный под-вариант (эксплуатирует градиент интенсивности): стимул «нужно мягко возразить» / «жёстко отказать» → пользователь выдаёт фразу нужной силы из лестницы.
- После каждой фразы — быстрая отметка: **easy / slow / failed** (вход в SRS-lite, §4.6).

### 4.3 Плеер — Режим 2: Listening drill (вспомогательный)
- TTS читает фразы по одной с паузами/повторами — для привыкания к звучанию.
- **Не** дефолт. Порядок: ordered / zone-random / full-random (рандом по умолчанию убивает градиент — поэтому осознанный выбор, а не автоматом).
- Озвучивается `phrase_en`; опционально keyword и gloss_ru (настройка).

### 4.4 Плеер — Режим 3: Контекст (генерация)
- Для каждой фразы LLM генерирует **предложение или короткий абзац** в реалистичном сценарии (инвест-встреча, стендап с командой).
- Поля управления качеством: `scenario_type`, `register`, `intensity`, `speaker_role`, `listener_role`, `context_length`.
- **Approval gate:** сгенерированный текст показывается с подсветкой фразы → пользователь одобряет → озвучивается TTS → кэшируется. **Одобренное не регенерируется автоматически** (иначе зашивается случайный кривой регистр). Кнопка «перегенерировать» — ручная.
- Генерация — онлайн, на переднем плане (не для фона).

### 4.5 Аудио-сессии (ядро мобильного UX)
- Кнопка **«Подготовить сессию»** перед метро/залом → сервер рендерит **gapless audio**: фраза, пауза, повтор, пауза, следующая — всё в одном потоке.
- Длинные батчи режутся на **блоки по 10–20 мин** (не один файл на 2 часа).
- Готовая сессия **пушится в Cache API устройства** → работает в авиарежиме / без сети.
- Клиент: один долгоживущий `<audio>` (playsinline), переход между блоками по событию `ended` с предзагрузкой следующего. **Никаких setTimeout-пауз** — все паузы внутри файла.

### 4.6 Мнема-вид
- Рендер `story_ru` с **подчёркнутыми якорями** по spans.
- Тап по якорю → раскрывается полная английская фраза (+ опц. озвучка).
- Режим самопроверки: якоря скрыты/заблюрены, пользователь вспоминает фразу, тап раскрывает.

### 4.7 SRS-lite (приоритизация, не Anki)
- 4 статуса фразы: **New / Shaky / Familiar / Automatic.**
- После Active Recall отметка easy/slow/failed двигает статус.
- Алгоритм подбора сессии чаще подсовывает Shaky/Failed, Automatic уходит в «retire». Без сложных формул интервалов.

### 4.8 Настройки
- TTS: голос (несколько голосов для вариативности акцента/интонации), скорость, модель (tts-1 / tts-1-hd).
- Drill: длина паузы, число повторов, порядок (ordered/zone-random/full-random), что озвучивать в listening.
- Генерация: дефолтные scenario_type/register/intensity/длина.
- LLM provider: выбор провайдера, модели, версии промпта.

## 5. Нефункциональные требования
- **Mobile-first, PWA** — установка на домашний экран, фоновое аудио. **Тестировать ОТДЕЛЬНО**: Safari tab и installed PWA (standalone фонит хуже). Fallback-подсказка: «открой в Safari для надёжного фона».
- **Offline-first:** core-сценарий (подготовленная сессия в метро без сети) обязан работать. Service Worker (app shell + аудио-кэш) + Cache API.
- **Фоновое аудио iOS:** реальный `<audio>` (не Web Audio как основной плеер), Media Session API **только** для метаданных/контролов замок-экрана. Учитывать: первый `play()` только по тапу; Low Power Mode рубит фон раньше.
- **Скорость/стоимость:** TTS-озвучка **предгенерируется** и кэшируется. Базовые фразы — сразу после approve батча; контексты — лениво/по кнопке; сессии — по кнопке перед выходом.
- **Стоимость:** OpenAI TTS — tts-1 $15 / 1M chars, tts-1-hd $30 / 1M (на личных объёмах копейки); генерация — Meridian (бесплатно через Max-подписку), фолбэк OpenAI.
- **Приватность:** один пользователь, HTTPS, пароль. Стоимостные эндпоинты не публикуются.

## 6. Архитектура и стек

- **Backend:** FastAPI (Python) — совпадает со стеком workspace (atmos_planning). SQLModel/SQLAlchemy + Pydantic, Alembic (или простой migration layer).
- **DB:** SQLite, но обязательно: **WAL mode, busy timeout, daily backup** (db-файл + папка аудио), миграции, export/import JSON, health-check. Без этого потеря volume = весь контент.
- **Файлы:** `/data/audio` (TTS-ассеты + рендеренные сессии), `/data/exports` (JSON-бэкапы батчей).
- **Frontend:** лёгкий mobile-first PWA — React + Vite. Audio через `<audio>` + Media Session API. Service Worker + Cache API для offline.
- **Reverse-proxy:** Caddy (авто-HTTPS) или существующий nginx на Hetzner. Поддомен `english.<domain>`. Basic-auth (один пользователь).
- **Деплой:** Docker-контейнер (паттерн workspace), отдельный prefix `english_*`.

### LLM provider abstraction
Интерфейс с методами `parse_batch` (сырой текст → JSON), `generate_context`, `repair_json`. Реализации: Meridian (дефолт), OpenAI (фолбэк), локальная модель / ручной импорт. Все LLM-выходы версионируются (provider, model, prompt_version). Снимает SPOF и ToS-риск «бесплатного прокси».

## 7. Интеграции
- **OpenAI TTS** (`tts-1` / `tts-1-hd`), ключ из master `.env`. Кэш аудио на диске.
- **Meridian** (Anthropic через Max, `172.17.0.1:3456`) — дефолт для парсинга батчей и генерации контекста. **Фолбэк** на OpenAI API при недоступности.

## 8. Модель данных (эскиз v1)
```

MnemoStory(id, batch_id, story_ru, spans_json)          # spans: [{anchor_id, phrase_id, start, end}]
```

## 9. Формат загрузки батча (paste → parse → approve)
Алексей вставляет сырой вывод Claude вида:
```
Раскладка ключей на фразы:
1. Understand → Help me understand the thinking there.
2. Walk → Walk me through how you got to that number.
...
Мнемо-текст: Ты хочешь UNDERSTAND гору, поэтому WALK ...
```
LLM-импортёр нормализует в строгий JSON (batch + zones + phrases + mnemo_story + spans), backend валидирует по схеме, UI показывает diff/таблицу, пользователь правит и **подтверждает**. После approve источник истины — JSON.

# ТЗ v2 — Реструктура в 3 урока (учебный flow)

> Статус: **v2 — после консилиума.** Opus (фоновый агент, сверял с реальным кодом) + GPT-4o + Claude-синтез.
> Дата: 2026-05-30.
> Контекст: v0.1–v0.3 построены и задеплоены. Self-recording + STT-скоринг (которые v1 откладывал) — **сделаны** (Тест A / Тест B). Появилось много элементов в 3 параллельных входах (Mnemonic-страница, Playback, Training) → клиента это путает («в разнобой»). Эта версия НЕ добавляет фичи — **переупаковывает существующее в один линейный путь.**

## v2.0 Главный разворот v1 → v2

1. **Было: 3 параллельных входа в батч** (Mnemonic / Playback / Training), дубли (shuffle ×2, recall ×2, список фраз ×3). **Стало: один линейный путь = 3 урока внутри батча** (вертикальная лестница). Лекарство от «в разнобой».
2. **Зачётный барьер переносится с Урока 1 в Урок 3.** Якорь (англ. глагол) — это указатель, а не содержание; зубрить последовательность якорей в отрыве от фраз = учить оглавление непрочитанной книги. Урок 1 кодирует **якорь+фразу вместе** (мягко), стена ≥7 — только в финале (Урок 3). Консенсус консилиума 3/3.
3. **Backend почти не трогаем** — endpoints `score-phrase`, `score-sequence`, `rotation/{batch_id}` и скоринг (gate → gpt-4.1-nano) переиспользуются. Вся работа — на фронте: перекладка компонентов из Mnemonic/Playback/Training в 3 экрана-урока + новая витрина батча + чистка дублей/роутов.

## v2.1 Структура: 3 урока

### Урок 1 — Мнемоническая основа (кодирование, мягкий gate)
1. «Послушай историю» → автозапуск **«Вся история»** (RU-нарратив + EN-якоря, караоке-подсветка). Обязательный первый контакт.
2. **Tappable-история**: тап по якорю раскрывает фразу (+ озвучка). ← якорь+фраза кодируются вместе.
3. «Послушай по порядку» → **«По порядку»** (якоря с паузами) — поймать ритм последовательности.
4. **Мягкий пересказ:** «Перескажи историю» → `score-sequence` → показываем score + пропущенные якоря + порядок **как зеркало, без блокировки.** Кнопка «Дальше» активна всегда.
- **Gate:** прослушал «Вся история» ≥1 раз + сделал ≥1 пересказ (любой балл). **НЕ ≥7.**
- **Прогресс:** «Историю прослушал ✓ · вспомнил 7/11 якорей».

### Урок 2 — Фразы (production, ядро заучивания)
1. **Список фраз перед глазами** (zone-grouped, единственная копия): якорь + фраза, тап → русский смысл, play на фразу. Контролы: play-all, shuffle, скорость.
2. **Кнопка «↻ Мнемоника»** (требование founder): перезапуск «Вся история» внутри Урока 2 — слушаешь → вспоминаешь, какая фраза где. Мост «мнемо ↔ фразы».
3. **Active recall (Тест B):** показывают якорь → говоришь фразу → STT → скоринг → «правильная фраза» + «что услышали» + «Дальше». Порядок — adaptive rotation (слабые фразы чаще).
4. **Лёгкий тест в конце:** один прогон Теста B по всем фразам.
- **Gate:** каждая фраза проговорена ≥1 раз **и** средний балл по батчу ≥6.
- **Прогресс:** «9/11 проговорены · средний 6.4 · слабые: Window, Outlier».

### Урок 3 — Тесты (active recall, mastery-gate)
1. **Mixed exam с random-stop:** играет мнемо-история; на ~30% якорей (случайно) плеер **встаёт на паузу** → «какой якорь? / какая фраза?» → говоришь **короткую форму** → скоринг. *Дизайн iOS-safe: запись идёт на паузе, на переднем плане, по тапу — никакого mic-в-фоне (см. v2.4).*
2. **Финальный пересказ (Тест A, зачётный):** перескажи всю историю → `passed = score ≥ 7`.

## v2.3 Навигация / IA

Экран батча `/batch/:id` = **лестница 3 уроков** (не меню фич):
```
Урок 1 · Мнемоническая основа   ✓
Урок 2 · Фразы                  ▶ 9/11
Урок 3 · Тесты                  ▶
```
- **Soft-lock, не hard-lock:** Урок 3 приглушён пока 1–2 не сделаны, но тапабелен (один пользователь — незачем запирать).
