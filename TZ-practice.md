# ТЗ — Раздел «Практика» (контекстный recall из пройденных бетчей)

> **Статус:** дизайн-док (UI + логика). Код НЕ пишем, пока не утвердим. Вопросы в бетчах — пока заглушки
> (формат + пример здесь; полные ~20×N генерим отдельной итерацией).
> Дизайн — строго по `DESIGN.md` (зелёный, премиум, voice-first, без геймификации).

## 1. Суть
Бетч пройден (3 урока закрыты, `l3_passed`) → фразы уже знакомы. «Практика» — следующий уровень:
достать **уместную фразу в моменте**, по реальной ситуации, **голосом**, и уметь дать **несколько разных**
вариантов (вариативность = настоящая беглость, а не одна заученная фраза).

Тест раздела: не «помнишь ли фразу?», а «в ответ на ситуацию выдаёшь подходящую фразу из репертуара бетча —
и можешь выдать ДРУГУЮ, если попросят». Цель — перенос из «знаю» в «достаю под давлением, гибко».

## 2. Навигация (решено: 4-й таб)
Нижний бар становится **4 таба + поиск**:
**Библиотека · Обучение · Практика · Профиль** + кнопка поиска.
- Текущий таб «Практика» (= карта-путь `/learn`) **переименовывается в «Обучение»** (роут `/learn` тот же).
- Новый таб **«Практика»** = этот дрилл (новый роут `/practice`).
- Иконки: Обучение — `IconSections`/волна-путь; Практика — микрофон/диалог (новая иконка `IconMic`/`IconDrill`).
- ⚠️ **Тесность:** капсула 56px на 4 таба узкая. План: иконки 21→19px, подпись 10→9px, gap плотнее,
  кнопка поиска 56→52px, поля дока 14→10px. Если визуально тесно — обсудим (возможен таб без подписи у иконки).
  Вся остальная стеклянная механика (liquid-pill, drag-to-select, lens-pop) сохраняется.

## 3. Что попадает в раздел
- Источник вопросов — пул из **всех пройденных бетчей** (`l3_passed === true`), вперемешку.
  **Никакого выбора бетча / настроек**: открыл вкладку → «Начать» → пошли вопросы.
  (Тренировка самого бетча по урокам — в другой вкладке «Обучение»; здесь — только живой опрос по освоенному.)
- Нет пройденных бетчей → empty-state: «Закрой первый навык в Обучении — и тренируй его вживую здесь».

## 4. Модель «вопроса»
Вопрос = ситуативный промпт (RU), на который уместный ответ — одна из фраз бетча.

```json
{
  "id": "q1",
  "prompt_ru": "Коллега назвал цифру, которая кажется завышенной. Попроси объяснить, как он к ней пришёл.",
  "intent": "curious-probe",            // что тренируем (для аналитики/подсказок)
  "accept_anchors": ["Run", "Understand"], // какие якоря бетча = валидный ответ; ПУСТО = любая уместная фраза бетча
  "difficulty": 1                       // 1..3 (опц.)
}
```
**Где хранить (рекомендация):** ОТДЕЛЬНО от контента бетчей, чтобы регенерация контента (соседний
консилиум-пайплайн) не затирала вопросы → `backend/content/questions/<slug>.json`. При импорте сидится в
таблицу `PracticeQuestion(batch_id, …)`. (Альтернатива — поле `practice_questions` прямо в бетче, но тогда
риск конфликта при перегенерации; не рекомендую.)

### Заглушки (✅ сделано)
- По 20 generic-промптов на каждый бетч контента — **73 файла, 1460 заглушек** в `backend/content/questions/`.
- Для заглушек `accept_anchors` можно оставить пустым (`[]`) = засчитывается любая уместная фраза бетча
  (матч по semantic-fit, §6). Реальные «острые» ситуативные вопросы с привязкой к якорям — отдельной
  итерацией (можно консилиумом, как контент).

### Пример (бетч «Лестница несогласия», якоря Understand/Run/Angle/Far/Hesitation/Pause/Land/Push/Straight)
```json
{
  "slug": "disagreement-ladder",
  "questions": [
    { "id":"q1", "prompt_ru":"Коллега уверенно назвал завышенную цифру. Мягко попроси объяснить, как он к ней пришёл.", "intent":"curious-probe", "accept_anchors":["Run","Understand"] },
    { "id":"q2", "prompt_ru":"Предлагают подход, с которым ты частично не согласен. Вклинься со своим ракурсом, не обесценивая.", "intent":"reframe", "accept_anchors":["Angle"] },
    { "id":"q3", "prompt_ru":"Идея звучит слишком радикально. Притормози мягко, выразив сомнение.", "intent":"soft-brake", "accept_anchors":["Far","Pause","Hesitation"] },
    { "id":"q4", "prompt_ru":"Партнёр давит. Пора прямо возразить — корректно, но без виляния.", "intent":"push-back", "accept_anchors":["Push","Land"] },
    { "id":"q5", "prompt_ru":"Нужно без обиняков сказать, что подход не сработает.", "intent":"blunt", "accept_anchors":["Straight"] }
    // … до ~20
  ]
}
```

## 5. UI-флоу (простой: одна непрерывная сессия)
Никакого грида/выбора бетча. Вкладка «Практика» = экран тренировочной сессии. Минимум кликов:
вошёл → отвечаешь голосом → видишь баллы.

### 5.1 Старт
- Экран с кнопкой **«Начать тренировку»** (или авто-старт при входе). Один тап → первый вопрос.
- Нет пройденных бетчей → empty-state (§3).

### 5.2 Сессия (основной экран)
- **Промпт-карточка**: текущий вопрос — ситуация (RU), из пула пройденных бетчей вперемешку.
  **Озвучка промпта голосом (TTS RU) — да** (voice-first; кэшируется на диске как у фраз).
- **Микрофон** (tap-to-record, iOS-safe по жесту, `RecFab` как в Уроке 3). Ответ голосом → STT → **балл 0–10**.
- Ответ **фиксируется в ленту текущей сессии** — строка: `вопрос → твой ответ (что услышали)` + **бейдж балла**.
  - Балл **≥8 → зелёный** (верно), **<8 → красный** (мимо). Порог = те же 80%, что в уроках.
- Сразу следующий вопрос. Лента сессии растёт (история попыток, новые сверху).
- **Внизу — живая статистика сессии**: отвечено N · средний балл X.X · 🟢 M / 🔴 K (· % верных).
- Кнопка **«Стоп / Завершить»** — закрыть сессию (опц. итог = та же статистика крупно).

### 5.3 Что НЕ делаем (упрощение по твоему описанию)
- Нет выбора бетча, нет настроек, нет грид-экрана, нет «вариант 1/K».
- Просто: вопрос → голосовой ответ → балл (🟢/🔴) → лента + статистика.

## 6. Логика оценки
1. **STT** (`gpt-4o-mini-transcribe`, en) → текст ответа.
2. **Балл 0–10:** semantic-fit ответа с фразами бетча-источника вопроса (реюз `scoring`/`score_phrase`),
   лучший матч `{anchor, score}`. **≥8 → зелёный**, **<8 → красный** (один балл по 10-балльной, цвет по порогу 8).
3. Каждая попытка → строка в **ленте сессии**; внизу агрегаты (кол-во, средний, 🟢/🔴, %).
4. **Анти-повтор (в MVP):** если ответ матчится на якорь, который уже зачтён 🟢 в этой сессии → не засчитывать
   как новый, показать «🔁 это уже было — дай другой вариант» и попросить переответить (балл не пишется в ленту
   до нового якоря). Тренируем вариативность: на одну ситуацию — разные фразы.

## 7. Backend (эскиз, НЕ пишем сейчас)
- Хранилище вопросов: `backend/content/questions/<slug>.json` → таблица `PracticeQuestion`.
- `GET /api/practice/{batch_id}` → вопросы пройденного бетча + фразы (для матчинга на клиенте/сервере).
- `POST /api/practice/score` → `audio + question_id + used_anchors[]` → STT + fit-score + repeat-check →
  `{ fits: bool, matched_anchor, score, is_repeat: bool, suggestion?: phrase }`.
- Реюз `scoring.score_phrase`; при необходимости новый `score_fit_in_batch(answer, batch_phrases, accept_anchors)`.
- Гейтинг по `l3_passed` — клиентский (личный тул; backend может не проверять).
- Дневной лимит скоринга — общий с уроками (`_check_rate`).
